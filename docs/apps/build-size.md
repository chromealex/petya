# Build size (`build-size`, «Размер билда»)

Local extension, category `gamedev`. Shows what an APK, AAB or IPA consists of and what grew between two builds.
No model, no network, no account: everything is computed by code.

## What it does
- Reads only the ZIP central directory (`zip.cjs`, dependency-free, streamed in 1 MB chunks, ZIP64 supported), so
  multi-gigabyte builds are never loaded into memory. Small entries (AndroidManifest.xml, Info.plist) and ELF
  section tables of uncompressed `.so` files are read on demand with size limits.
- Version and identity: APK binary AXML manifest, AAB aapt2 protobuf manifest, IPA Info.plist (XML or binary).
- Categories: native libs per ABI, dex, app binary (IPA), Frameworks, Unity Data (`assets/bin/Data`, `Data/`),
  Addressables (`aa/`), StreamingAssets (`Data/Raw` on iOS; on Android they land in `assets/`), other assets,
  resources (`res/`, `resources.arsc`, `.car`, `.lproj`), debug symbols, other. Compressed and uncompressed sizes.
  AAB: per-module sizes (base, feature modules, asset packs).
- One build → breakdown with the 15 largest files. Two builds → diff: which is older is decided by
  versionCode/CFBundleVersion, then version name, then numbers in the file name, then mtime (the card says which).
  Top 15 grown files, category deltas, new/removed counts.
- Warnings: uncompressed `.so` in an APK, x86/x86_64 ABIs, duplicate files (same CRC and size), huge single assets,
  debug symbols (dSYM, `.sym`, `Symbols/`, and `.symtab`/`.debug_*` sections in stored `.so`). AAB symbols in
  BUNDLE-METADATA are reported as info (not shipped).
- Every card says that store download size differs (split APKs / App Thinning).
- Card actions: «Показать все файлы» (top 300 by size or by change), «Что сжать?» (rule-based advice from the card),
  «Сравнить с другим…» (file picker, then an ordinary chat request with the paths).

## Inputs
1. Chat attachments picked from disk (their `localSourcePath`). An attachment without a path → a question.
2. Paths in the request: quoted («…», "…", `…`), absolute/`~` paths, or a bare file name found in the project.
3. The current chat project's folders (`project-folders.cjs`): bounded walk (depth 7, 5000 dirs, skipping
   Library/Temp/node_modules/.git/…), newest build first. «Почему билд вырос» takes the two newest of one type.

## Phrases
«почему билд вырос», «сравни размер этих двух apk», «из чего состоит ipa», «размер билда», «сколько весит apk»,
«Что сжать в этом билде?». Near-misses returning null: «размер команды», «размер экрана», «сборка упала»,
«время сборки выросло», «билд собирается дольше».

## Limits
- Download size is not computed (needs bundletool / store data); the card explains this.
- Debug sections are checked only in stored (uncompressed) `.so`; compressed ones would need full inflation.
- Big builds cannot be attached through the composer (10 MB attachment limit); use a path, the project folder or
  «Сравнить с другим…».

## Verified
Unit (`node tests/build-size.cjs`) on synthetic fixtures generated by `tests/fixtures/build-size/make.py` (real ZIP,
AXML, protobuf, binary plist, ELF) plus a hand-built ZIP64 directory. UI (`tests/build-size-ui.cjs`) renders cards
from the fixture analysis in the real Electron chat and saves `petya-build-size.png` / `-2.png` in the temp folder.
Not yet checked on real production builds of several GB.
