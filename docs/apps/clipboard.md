# «История буфера» (`clipboard`)

Category: «Компьютер и файлы». A local history of copied text and pictures, off until the user switches it on.

## Privacy

- **Opt-in**: `clipboardHistory` is `'false'` after adding the app. It is switched on only by the user: the switch in
  the app's settings, «Включить историю» on a card, or «Включить историю» in the consent question a chat request asks.
  What was on the clipboard when watching started is not recorded.
- **Never kept** (`secrets.cjs`, decided before storing):
  copies marked by their app (macOS `org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType`,
  1Password's type; Windows `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory`,
  `Clipboard Viewer Ignore`); copies made while a password manager (the activity tracker's list,
  `src/activity/redact.cjs`) or an app from the user's own list (`clipboardPrivateApps`) is in front; text that looks
  like a secret — private keys, `password: …` / `token=…` lines (not references such as `process.env.X`), credentials
  in URLs, `Bearer …`, tokens with documented service prefixes, JWTs, single words mixing letters, digits and symbols
  or long high-entropy strings. Code identifiers, links, ids, hashes, UUIDs and versions are kept. Only counts of
  skipped copies are kept, never their content.
- **Local and encrypted**: `<company data>/extensions/clipboard/history.json` and `images/<id>.bin`, encrypted with
  Electron `safeStorage` when available (otherwise plain, 0600). Nothing is sent anywhere.
- **Limits**: the last 200 copies, none older than 7 days (checked on every add and read; pictures go with their rows).
  Copying the same thing again moves it to the top. Pictures are kept at ≤ 1600 px with a small preview.
- **Pause** (an hour or until resumed, `clipboardPausedUntil`) and **«Стереть всё»** (asks first; deletes the list and
  the pictures).

Watching: Electron has no clipboard event, so the clipboard is read every 1.5 s while history is on and not paused
(`watcher.cjs`); a picture is read only when there is no text and the clipboard says it holds an image. Petya's own
writes are taken as seen and never recorded.

## Link → task (`task-tracker`)

The card calls `k.links('task-tracker', {issue, comment, title}, {context:{comment:true}})`. The Jira provider
(`src/extensions/jira/task-tracker.cjs`) now accepts `{issue, comment}`: on the press it re-checks the connection and
posts `POST {site}/rest/api/3/issue/{key}/comment` with an ADF body (API token Basic auth, or Petya's Atlassian OAuth
through the shared request), answering `{done, key, url, text}`; the card then hides the button and links the issue.
Asana does not offer comments (`fits` refuses `{comment:true}`).
