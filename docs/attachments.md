# «Петя, посмотри вот это»

Файл можно выбрать кнопкой «Показать файл», перетащить в окно или вставить скриншот из буфера. Затем задайте вопрос в поле команды, нажмите «Разобрать вложения» либо скажите «Петя, посмотри вот это». Пока есть прикреплённые файлы, следующая команда разбирается как вопрос к ним. Чтобы перейти к обычным действиям, уберите ненужные вложения.

Поддерживаются TXT, MD, LOG, CSV, JSON, XML, YAML и распространённые текстовые форматы кода; DOCX (основной текст), PDF с текстовым слоем; PNG, JPEG и WebP; видео MP4, MOV, WebM. До 5 файлов: документы/изображения по 10 МБ, видео по 100 МБ без ограничения в 180 секунд. Для PDF читаются первые 30 страниц и максимум 40000 символов, для текстов — 40000 символов на файл, суммарно до 60000 на запрос. Петя сообщает об ограничениях. Текст PDF извлекает встроенный PDF.js 6.5.438 (лицензия Apache-2.0 в src/vendor/pdfjs/LICENSE), без внешних программ и сетевого сервиса. DOCX читается без исполнения макросов или распаковки на диск; форматирование, изображения и сноски не учитываются. Сканы PDF без текста требуют изображения нужной страницы.

Скриншоты уменьшаются до 1600 пикселей по длинной стороне. Они передаются только локальной Ollama-модели с capability vision. Если такой модели нет, в разделе вложений доступна кнопка «Подготовить модель для скриншотов»: она скачивает gemma3:4b через Ollama (несколько гигабайт) и показывает ход подготовки. Загрузку можно остановить и повторить. Текстовая модель Пети не меняется. Облачные модели Ollama для вложений отклоняются. Качество распознавания изображений зависит от выбранной локальной модели; мелкий текст может быть неразборчив.

Разбор создаёт отдельную тему. В ней можно задавать уточнения, возвращаться к ней после перезапуска и удалить её кнопкой «Удалить эту тему и её вложения». Содержимое и ответы сохраняются вместе с темой в зашифрованном хранилище ОС и удаляются по общему сроку хранения контекста. Оригинальные файлы не изменяются. До начала разбора вложения лежат только в памяти, до 30 минут или выхода из приложения. Удаление темы удаляет также извлечённый текст и нормализованные изображения.

Файлы — данные, а не инструкции: Петя не исполняет код, макросы или команды из них. Автоматическая передача вложений Claude/Codex и в веб-поиск отсутствует. Если локальная модель не готова, тема сохраняется с понятной ошибкой, после настройки можно повторить вопрос.

Проверки: DOCX, ограничения и время жизни вложений, отсутствие vision/облачной модели, IPC создания/удаления темы, текстовый PDF с кириллицей в настоящем Chromium, регрессионные тесты интерфейса. Ответ текстовой модели проверяется на синтетическом файле. Реальная vision-модель не загружалась автоматически.

## Скриншоты, ошибки кода и видео

Для больших скриншотов общий вид дополняется фрагментами исходного разрешения (до шести плиток 1280×1280, если изображение целиком помещается в них). Это помогает читать мелкие ошибки и код. Для более длинных/больших скриншотов Петя просит крупный фрагмент. Это распознавание vision-моделью, а не гарантированно точный текстовый парсер: неразборчивые символы должны отмечаться явно.

Видео MP4, MOV, WebM — до 100 МБ, 16 Мп; ограничение в 180 секунд снято. Декодирование выполняется скрытым sandboxed Chromium без сети и воспроизведения звука пользователю. Неподдерживаемый кодек возвращает ошибку; предпочтительны MP4/H.264 и WebM. Сохраняются до 12 равномерных кадров до 1600 px с временными отметками; исходный ролик не сохраняется. Выборка может пропустить короткое событие: для точного момента прикрепите короткий фрагмент или скриншот. Речь распознаётся локальным Whisper по фрагментам с временными отметками и учитывается вместе с кадрами. Подробности и ограничения — в video-audio.md.

При нескольких изображениях каждый вид сначала анализируется отдельно, затем локальная модель сводит наблюдения в итог. В запросе сохраняются имя файла, метка кадра/области, контекст исходного обсуждения и вопрос. Разбор выделяет видимый текст ошибки, фактическое поведение игры/интерфейса, гипотезы и недостающие шаги воспроизведения. До 24 кадров/видов на один разбор. Модель должна отличать наблюдаемый симптом от доказанной причины. Автоматическая установка vision-модели не выполняется; используйте существующую кнопку подготовки модели.

## Медиа из Telegram и Slack

Кнопка «Медиа из Telegram / Slack» показывает до 80 недавних вложений из синхронизированных чатов текущей компании. Telegram: только выбранные чаты текущего подключённого аккаунта. Slack: только текущая выборка каналов, доступ проверяется заново перед загрузкой сообщения. Требуется право files:read. Файлы из внешнего хранилища Slack не скачиваются. Токен Slack передаётся только files.slack.com, перенаправления запрещены; размер ограничен как по метаданным, так и во время чтения.

Можно сказать «разбери видео из телеграма» или «посмотри скрин из слака». Если вложений несколько, Петя предлагает список. Чат и его сохранённый текст добавляются к источнику файла; при изменении подключения или удалении контекста незавершённый импорт отбрасывается. Синхронизация Telegram собирает только метаданные медиа; скачивание и анализ происходят по запросу.

Проверки: настоящий синтетический WebM, временные отметки и разные кадры, отказ на повреждённом видео, фрагменты скриншота; тестовые ответы модели, проверка границ источников/размера, сообщения Telegram только с медиа. Реальные сообщения и пользовательские ролики при тестах не скачивались; качество анализа реального бага зависит от локальной vision-модели.
