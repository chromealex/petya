# Git в Пете

Git автоматически определяется по локальным папкам контекста текущего проекта. Отдельное подключение Git в настройках не нужно. Кнопка **Git** в чате открывает панель проекта и сразу запускает поиск. Поддерживаются несколько папок, вложенные репозитории, папка внутри репозитория и Git worktree. При нескольких репозиториях Петя предлагает выбрать конкретный; выбор относится только к текущему проекту и набору его папок.

Если Git не найден, Петя сообщает об этом и предлагает «Создать Git» с конкретной папкой. Только нажатие этой кнопки или явная команда «создай git для проекта» запускает `git init -b main`. При нескольких пустых папках требуется выбор. Файлы не добавляются в индекс, коммит не создаётся, remote не настраивается. Если системный Git отсутствует, показывается отдельная ошибка установки программы.

Поиск вложенных репозиториев ограничен 1000 каталогами и четырьмя уровнями; скрытые каталоги и каталоги зависимостей/сборок пропускаются, символические ссылки при обходе не раскрываются. При ошибках доступа или достижении лимита Петя сообщает о неполном поиске и не предлагает создавать репозиторий на основании такого результата.

Используется установленный системный Git; автор коммитов, SSH-ключи и credential helpers берутся из его настроек.

Панель показывает ветку и изменённые файлы. Отметьте нужные файлы и нажмите «В коммит». «Убрать из коммита» меняет индекс, сохраняя рабочие файлы. Напишите сообщение и нажмите «Создать коммит». «Diff» показывает изменения отслеживаемых файлов вне индекса; «Diff коммита» — подготовленные изменения. Содержимое новых неподготовленных файлов в Git diff не отображается. История содержит последние 30 коммитов; большие ответы ограничены и помечены как фрагменты.

Можно создавать ветки, переключаться между локальными ветками, после Fetch выбирать удалённые ветки для создания локальной tracking-ветки, выполнять Fetch/Pull/Push в выбранный remote. Переключение существующих веток и Pull требуют чистой рабочей папки. Pull допускает только fast-forward; расхождение истории возвращает ошибку, без автоматического merge/rebase/stash. Push отправляет текущую ветку в её upstream либо одноимённую ветку выбранного remote. Force-push, удаление веток, reset/clean, произвольная командная строка, clone и автоматическое разрешение конфликтов не реализованы.

Примеры команд чата:

- «Статус гита», «Покажи diff», «История коммитов», «Покажи ветки».
- «Добавь в коммит src/example.js», «Убери из коммита src/example.js».
- «Сделай коммит: Исправлен вход» — только уже подготовленные файлы.
- «Создай ветку feature/login», «Переключись на ветку main».
- «Git fetch», «Git pull», «Git push origin».

Команды записи выполняются по явной команде или нажатию кнопки. Модель не конструирует shell-команды: аргументы передаются напрямую системному Git. Отрицания, цитаты и вопросы о командах не выполняются. Для нескольких remote без upstream требуется выбор. При смене проекта или обнаруженном изменении HEAD, ветки, индекса либо списка изменений панель требует обновить состояние. Одновременно выполняется одна операция на репозиторий. Внешние изменения из других Git-клиентов нельзя полностью заблокировать; перед записью Петя проверяет доступный снимок состояния.

Проверки: реальные временные репозитории и локальный bare remote, начальный коммит, выбор файлов, unstage без удаления, имена с пробелами, переименование, защита устаревшего снимка и смены проекта, ветки, fetch/pull/push, отказ при расхождении истории. В настоящем окне Electron проверены список файлов, stage, commit, история и создание ветки через чат. Рабочие репозитории пользователя тесты не изменяют.

Семантика команд: [Git status](https://git-scm.com/docs/git-status), [Git pull](https://git-scm.com/docs/git-pull).

Дополнительно проверены отсутствие автоматического init, явное создание в выбранной папке, несколько папок и репозиториев, поиск во вложенных каталогах, родительский репозиторий, worktree, устаревший контекст и пропуск симлинков.

Исправление маршрутизации: разговорные просьбы вроде «А сейчас можешь гит посмотреть», «Можешь проверить репозиторий?» и «Какая сейчас ветка?» вызывают чтение Git. Все распознанные команды Git исключены из фонового текстового диалога, обходившего обработчики инструментов. Теоретические вопросы, отрицания и цитаты не выполняют команды. Явные просьбы «можешь сделать push» и «создай коммит с сообщением …» вызывают соответствующую операцию, а при отсутствии параметров Петя просит указать их. Регрессия проверена через обычную отправку сообщения в окне Electron с настоящим временным Git-репозиторием.


Проверка естественных Git-просьб: 53 сценария через обычную отправку чата в Electron, из них 46 вариантов операций, 3 запроса недостающих параметров и 4 запроса без выполнения операций (отрицания, теория и цитаты). Для каждой операции проверялся реальный вызов Git и его результат: индекс, ветка, коммит или remote. Fetch/pull/push использовали временный локальный bare remote. Отчёт: `docs/git-natural-report.json`.

Примеры: «Можешь показать изменения в файлах?», «Что войдёт в коммит?», «Давай заведём ветку feature/test», «Можешь убрать файл src/a.js из коммита?», «Можешь сделать коммит с сообщением “Исправлен вход”?», «Подтяни изменения из origin», «Давай запушим изменения». Несколько файлов перечисляются через запятую; имена с запятыми нужно брать в кавычки. «Добавь все изменения в коммит» подготавливает текущие неподготовленные изменения; уже подготовленные удаления сохраняются. Составные команды с несколькими действиями нужно выполнять по одной.
