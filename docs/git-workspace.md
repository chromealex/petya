# Git в Пете

В **Настройки → Сервисы → Git** доступен репозиторий выбранного проекта чата. Подключите корневую папку репозитория в настройках проекта и нажмите «Обновить». Используется установленный системный Git; автор коммитов, SSH-ключи и credential helpers берутся из его настроек.

Панель показывает ветку и изменённые файлы. Отметьте нужные файлы и нажмите «В коммит». «Убрать из коммита» меняет индекс, сохраняя рабочие файлы. Напишите сообщение и нажмите «Создать коммит». «Diff» показывает изменения отслеживаемых файлов вне индекса; «Diff коммита» — подготовленные изменения. Содержимое новых неподготовленных файлов в Git diff не отображается. История содержит последние 30 коммитов; большие ответы ограничены и помечены как фрагменты.

Можно создавать ветки, переключаться между локальными ветками, после Fetch выбирать удалённые ветки для создания локальной tracking-ветки, выполнять Fetch/Pull/Push в выбранный remote. Переключение существующих веток и Pull требуют чистой рабочей папки. Pull допускает только fast-forward; расхождение истории возвращает ошибку, без автоматического merge/rebase/stash. Push отправляет текущую ветку в её upstream либо одноимённую ветку выбранного remote. Force-push, удаление веток, reset/clean, произвольная командная строка, clone/init и автоматическое разрешение конфликтов не реализованы.

Примеры команд чата:

- «Статус гита», «Покажи diff», «История коммитов», «Покажи ветки».
- «Добавь в коммит src/example.js», «Убери из коммита src/example.js».
- «Сделай коммит: Исправлен вход» — только уже подготовленные файлы.
- «Создай ветку feature/login», «Переключись на ветку main».
- «Git fetch», «Git pull», «Git push origin».

Команды записи выполняются по явной команде или нажатию кнопки. Модель не конструирует shell-команды: аргументы передаются напрямую системному Git. Отрицания, цитаты и вопросы о командах не выполняются. Для нескольких remote без upstream требуется выбор. При смене проекта или обнаруженном изменении HEAD, ветки, индекса либо списка изменений панель требует обновить состояние. Одновременно выполняется одна операция на репозиторий. Внешние изменения из других Git-клиентов нельзя полностью заблокировать; перед записью Петя проверяет доступный снимок состояния.

Проверки: реальные временные репозитории и локальный bare remote, начальный коммит, выбор файлов, unstage без удаления, имена с пробелами, переименование, защита устаревшего снимка и смены проекта, ветки, fetch/pull/push, отказ при расхождении истории. В настоящем окне Electron проверены список файлов, stage, commit, история и создание ветки через чат. Рабочие репозитории пользователя тесты не изменяют.

Семантика команд: [Git status](https://git-scm.com/docs/git-status), [Git pull](https://git-scm.com/docs/git-pull).
