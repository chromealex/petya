## Состав и критерии

Код и логи: 25 разных логов и 25 фрагментов кода, к каждому два независимых вопроса — найти проблему и предложить конкретное исправление/проверку. Всего 100 проверок. Есть исправные материалы, неоднозначность причин и посторонние инструкции внутри файлов. Языки: JavaScript, Python, C#, SQL; логи сети, прав, памяти, базы, сборки, Android и Unity.

Изображения: 50 настоящих PNG и 100 независимых вопросов. Десять категорий: консольные ошибки, доски задач, графики, таблицы, мониторинг, валидация форм, стек ошибок, недостаточные сведения, посторонние инструкции, схемы зависимостей. PNG передавались в локальную vision-модель через production readImage; текст HTML и эталонные ответы ей не передавались. В основном это читаемые рабочие скриншоты с английскими подписями и русскими вопросами, не фотографии или бенчмарк любого OCR.

Для обеих версий применены одинаковые конечные критерии. После просмотра ответов уточнены допустимые формулировки (например, код 429 без префикса HTTP, русский перевод названия поля) и добавлены проверки обнаруженных ложных утверждений. Исходная оценка каждой строки также сохранена. Совпадение ключевых признаков не гарантирует безошибочность всего объяснения; ниже отдельно перечислены ограничения и оставшиеся сбои.

## Изменения

- Разделены инструкции анализа точного текста, чтения изображения и ответа по наблюдениям. Текстовые файлы больше не предлагается читать как OCR.
- Для технических файлов при наличии выбирается локальная qwen2.5-coder:7b; основной разговорный режим не меняется. Для изображения gemma3:4b извлекает наблюдения, затем выбранная текстовая модель (в прогоне qwen3:4b) отвечает на вопрос. Модели подготовлены локально; автоматического скачивания при открытии файла нет. [Карточка специализированной модели](https://ollama.com/library/qwen2.5-coder:7b).
- Ссылки sourceLines проверяются по имени и существующему номеру; исходная строка копируется приложением дословно. Неизвестные/неоднозначные файлы и номера отбрасываются. Это не проверка истинности диагноза.
- Пустой, невалидный или оборванный по лимиту ответ повторяется максимум один раз. Сетевая ошибка не маскируется повторной генерацией.
- Из полностью пронумерованных блоков предложенного кода убираются служебные номера строк, чтобы блок можно было копировать; явно запрошенная нумерация сохраняется. Одно слово без источника вместо запрошенного разбора отклоняется с повтором. Это ограниченная проверка формы ответа, не универсальная защита от инструкций в файле.
- SQL, CJS/MJS, JSX/TSX, Java, Go, Rust, C/C++ и shell читаются как обычный текст без обучения внешнему формату.

Первый прогон кода использовал прежний обработчик с qwen3:4b, итоговый — исправленный обработчик и qwen2.5-coder:7b. Поэтому это сравнение рабочего процесса целиком, не независимый эксперимент только с промптом или только с моделью. Веса моделей не дообучались. Между полными прогонами были целевые проверки и неудачные варианты инструкций; итоговая таблица использует последние полные прогоны и последующий целевой контроль шести случаев после добавления проверки бессодержательного ответа и очистки номеров строк в предложенном коде. Предыдущие результаты этих шести случаев сохранены; они не заменялись на лучшие попытки. Положительные критерии оценивают сам ответ, без автоматически добавленных исходных строк. Ручные замечания об ошибочных объяснениях и неполных исправлениях понижают итоговую оценку и сохранены в JSON.

## Воспроизведение

- `npm run test:materials` — проверки обработки, локальности моделей, ссылок на источник, повторов и чтения форматов.
- `npm run test:logs:live` — 100 тестов кода и логов.
- `npm run test:images:live` — 100 тестов PNG.
- `PETYA_REPORT` задаёт JSON-отчёт; `PETYA_MATERIAL_IDS=11,35` выбирает случаи. Требуется запущенная Ollama. На Mac с системным Node 14 можно запускать `env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/Electron.app/Contents/MacOS/Electron tests/material-analysis-live.cjs images`.
- Фикстуры: `tests/fixtures/material-analysis/`; отчёты: `docs/material-code-{before,after}.json`, `docs/material-images-{before,after}.json`.

Остались ограничения небольших локальных моделей: возможны неверный диагноз, неполное исправление, потеря поля и ошибочный подсчёт элементов. Запрос крупного фрагмента учитывается как неуспех, если поле на тестовом изображении было читаемым. Этот набор не доказывает защиту от всех инструкций в документах, качество произвольных фотографий или правильность предложенного исправления на полном проекте.
