# Understanding new phrasings

Petya uses a ready-made local Ollama model to choose a tool based on the meaning of a request. The neural network is not fine-tuned: it is given the tool descriptions, the current company, the last four utterances of the active topic and the names of configured mail skills. Secrets and settings of other companies are not passed. Cloud models are rejected for this router.

Familiar commands, clarifications, trained phrases and task-creation actions are handled by the existing mechanisms. For other requests, the model chooses between reading Jira bugs, Google Play ANRs, Gmail via an existing skill, searching public information, a summary, ordinary dialog, or a clarifying question. Free-form code, writing to services and arbitrary OS commands are not part of this catalog. Integrations are checked by the existing code; for a service that is not connected, Petya offers to connect it or to read it through the built-in browser. The search query is taken from the current phrase, without the model adding the company's history.

An invalid model response does not launch a new tool. If Ollama is unavailable, the previous handling remains; an error getting a response is shown to the user. The model's confidence does not guarantee a correct choice. Understanding does not add missing tools: a new service still requires an implementation or available browser reading.

In «Подключения → Ollama» (Connections → Ollama) you can turn off «Понимать новые формулировки через модель» (Understand new phrasings via the model) or prepare Qwen3.5:9B. The current model is replaced only after a successful download and a test response. The cancel button keeps the previously selected model. On smaller computers a smaller local model can be used. The tool-selection setting is saved separately for each company.

Checks: tests of the restricted catalog, validation, the clarification threshold, mail skill selection and a single handler call; a check that updating the model does not lose the previous selection on error; the full test suite and Electron UI smoke. On the installed Qwen3:4B, six requests (bugs, ANR explanation, negation, summary, web, real ANRs) selected the expected tools. This is a small routing check, not a guarantee of accuracy on arbitrary speech and not a test of real accounts.
