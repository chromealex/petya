# Team

The separate «Команда» (Team) tab works independently of the Jira and Slack connections. Add up to 100 colleagues: name, familiar name variants, role, projects, responsibilities, email, and optional Slack member ID / Jira accountId. Changes and deletions are applied after «Сохранить команду» (Save team).

The former Jira field «Кто за что отвечает» (Who is responsible for what) is available in the team's additional information; its contents are kept without automatic parsing. Cards are stored encrypted in the settings using OS facilities; the additional information is stored like the former settings. The team is not deleted when the temporary context is cleared.

The directory is passed to the local model in dialogue and when preparing/editing Jira tasks. Names are added to the speech-recognition hint. When clarification through Claude/Codex is enabled, a limited fragment of the directory may be sent to the selected assistant along with the question. For large teams the context is limited; matches with the question come first.

Examples: «Кто отвечает за Android?» (Who is responsible for Android?), «Чем занимается Полина?» (What does Polina work on?), «К кому идти с вопросом по релизу GAME?» (Who should I go to with a question about the GAME release?). The answer is generated by the model from the entered information. When there are several candidates, Petya must ask to clarify the project or the person. Information about a permanent role does not confirm the current assignee of a specific build. Adding a contact by itself does not send messages or assign tasks; the existing checks of available Jira assignees remain. Automatic selection of the recipient for a build question still uses the latest Slack thread.


## Filling in by voice

Say «Петя, заполни команду» (Petya, fill in the team). Petya uses the saved context of the current company, notes about the team, the user's messages in the current topic, and the text of attached documents. If Slack is connected, the command without additional data first reads the members of the selected work channels and their Slack profiles. This is a separate directory read, not a synchronization of message history. Roles and contacts are not guessed: every field must be confirmed verbatim by a quote from a source. With a large volume, the first 32 thousand characters of the selected sources are considered, so the result may be incomplete.

New colleagues and empty fields are saved immediately. In case of a conflict Petya asks a question; answer «замени» (replace) or «оставь прежнее» (keep the old one). You can answer by voice or text. Namesakes without an unambiguous identifier are not merged. A clarification is valid for 10 minutes and is cancelled when the company changes or the directory is modified.

Extracting from arbitrary discussions requires a configured Ollama. Without a model you can dictate a list: «Заполни команду: Полина — тестирование; Иван — серверная часть» (Fill in the team: Polina — testing; Ivan — server side). If data is insufficient, Petya will ask you to name colleagues. The list on screen updates automatically; unsaved manual edits are not overwritten.


## Team from Slack

«Петя, заполни команду» (Petya, fill in the team) with Slack connected fetches the current members of the configured channels. «Заполни команду из Slack #разработка» (Fill in the team from Slack #development) selects a specific channel. Bots and deactivated accounts are skipped. Name, display name, title, Slack ID, and available email are taken directly from the profile, without a language model. A channel name is not treated as a project, and a title is not turned into invented responsibilities.

If there are no channels or the selection is too broad (more than 100 colleagues), Petya will ask to specify a channel. On an API error or incomplete loading, nothing is saved. The users:read scope and read scopes for the corresponding channels are used; email is filled in only if Slack returns it. Existing conflicts are clarified by voice.

API: [channel members](https://docs.slack.dev/reference/methods/conversations.members/) and [user profiles](https://docs.slack.dev/reference/methods/users.list/). If an old connection lacks users:read, it must be reconnected with this scope; the Slack app template now includes it.


A channel purpose («разработка» (development), «QA») is resolved taking into account the project of the current topic and the source Slack thread. For example, with project BW the word «разработка» selects `jw-bw-dev`, not `jw-mw-dev`. If the project is not set or the mapping is unknown, Petya reads out the options; you can answer «первый» (first), «второй» (second), with an exact name, or with a unique project key. An exact name with `#` takes priority. The general fill-in command no longer merges several ambiguous channels automatically.


## Project memory

Links are stored in the encrypted `project-memory.json` separately for each company. Project and channel names are arbitrary; BW/MW mappings are not hardcoded in the program.

- «Работаем над проектом Альфа» (We're working on project Alpha) — select or remember the project and open a clean topic.
- «Работаем над другим проектом» (We're working on another project) — Petya will ask for the name by voice.
- «Запомни канал разработки #точное-имя» (Remember the development channel #exact-name) — check the available channel and save its ID.
- «Нет, по этому проекту пишем #другой-канал» (No, for this project we post in #other-channel) — correct the last Slack link.
- «Запомни проект Jira ABC» (Remember Jira project ABC) — check the project against those selected in the Jira connection.
- «Запомни репозиторий /полный/путь» (Remember repository /full/path) — link an existing Git repository. An HTTPS link is also saved, but is not cloned or run automatically.
- «Запомни участника Иван Иванов» (Remember member Ivan Ivanov) — link an existing team card.
- «Покажи связи проекта» (Show project links), «Забудь канал разработки» (Forget the development channel), «Забудь репозиторий» (Forget the repository), «Забудь проект Альфа» (Forget project Alpha) — view or delete memory without deleting service data.

The saved Slack channel is used when filling in the team; an exact channel in the command takes priority. Several matching links, an unavailable channel, or a change of connection require clarification. A new ordinary topic does not inherit the project. Jira and the local repository are taken into account for actions from a project topic. A repository is matched only with projects already available to the executor. Members are currently saved as references to cards, without automatic task assignment. Channel memory does not replace the existing addressing for sending messages to the source thread.


## Requests in Slack

«Петя, попроси разработку заполнить команду» (Petya, ask development to fill in the team) sends a request to provide names, roles, and work contacts. Other requests: «Попроси QA проверить релиз» (Ask QA to check the release), «Попроси #точный-канал проверить отчёт» (Ask #exact-channel to check the report). The free-form part of the request is passed on without additions from the model; mass mentions are not added.

Confirmed project links take priority over name matches, and an exact channel in the command takes priority over links. Without a work context, with several options, or with an unavailable link, Petya offers up to eight channels; answer with a number, a name, or «отмена» (cancel). The choice is re-checked before sending and expires after ten minutes. Changing the topic or connection cancels the old choice. Choosing a channel for a one-off request does not change project memory: for a permanent link use «запомни канал разработки …» (remember the development channel …).

If the channel matches the source Slack thread, the request is sent there; otherwise as a new message. The report contains a link. The company's encrypted log blocks repeating the same text in the same channel/thread for 15 minutes, including across app restarts. On a network error or an unconfirmed result, automatic resending is prohibited indefinitely; check the channel via the link. An explicit rejection from Slack allows repeating the command after fixing the connection.

Requests do not trigger automatic import of replies or reminders to colleagues. These features are not implemented yet.


### Role-based recipients and colloquial names

«Попроси клиентских разрабов посмотреть свои задачи в жире» (Ask the client devs to look at their tasks in Jira, using the slang «жира» for Jira), «Попроси всех разрабов проверить задачи» (Ask all devs to check the tasks), «Попроси куашников проверить релиз» (Ask the QA folks to check the release) now find a group of people and add personal mentions. Supported: «клиенских» (a common misspelling of "client"), «клиентских разработчиков» (client developers), «фронтенд разрабов» (frontend devs), «серверных разрабов» (server devs), QA and testers. «В жире» (in Jira, slang) in the request text becomes «в Jira»; this command does not read or modify the Jira tasks themselves.

Petya fully loads the members of the selected channel and their Slack profiles. Roles are taken from team cards and, if absent, from profile titles. Client development is recognized by explicit indications of client/Frontend/Unity/iOS/Android development; QA is not considered development even with the title QA automation engineer. Names by themselves do not serve as proof of role or identity. Cards are matched by Slack ID or by a single exact email. An explicitly different project is excluded; saved project members are also taken into account. Bots and deleted accounts are not mentioned.

The list covers all found members with a confirmed role; an empty title does not allow guessing the specialization. If a known member of the required role is not matched with Slack, or a project member is missing from the channel, sending stops with an explanation — a partial list is not sent. Incomplete pagination or a change of topic, permissions, or directory also stops the action. The report lists those who were tagged. «Попроси разработку …» (Ask development …) and «попроси тестирование …» (ask testing …) keep sending to the channel without personal tags; names of groups of people include mentions.

Mentions are formed only from verified IDs according to the [Slack format](https://docs.slack.dev/messaging/formatting-message-text/#mentioning-users). User text is escaped separately: mention constructs passed in it do not turn into additional tags.
